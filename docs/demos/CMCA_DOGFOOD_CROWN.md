# CMCA v26.9.17 Self-Dogfood Crown

## Executive demo contract

This court demonstrates one narrow claim at repository scope:

> A CMCA planning/execution class that is UNKNOWN to the current
> MachineExperience compiler can be resolved and verified once, compiled into
> deterministic experience, and then replayed for the equivalent semantic
> subject without invoking the frontier resolver again.

It does **not** claim production deployment, external-system actuation, merge,
publication, or portfolio-wide SA2A ALIVE standing.

## The eight repo-native CMCA surfaces

The crown uses the same eight operational surfaces already pinned by
`tests/benchmarks/test_cmca_eight_use_cases_benchmark.py`:

1. Closed-Loop AutoDev CI/CD Loop.
2. High-Frequency In-Process Swarm Dispatch.
3. BEAM Cluster Cross-Host Interop.
4. Adversarial Defect Repair Frontier.
5. Deceptive Multi-Armed Frontier.
6. High-Dimension Prime Budget Conservation.
7. Embedded AtomVM Microcontroller Projection.
8. Object-Centric Process Mining Conformance.

## Two episodes

### Episode 1 — UNKNOWN frontier

Each semantic use-case contract is absent from the fresh
`MachineExperienceCompiler`.

The case is run against the actual repository-native surface. Only after its
native verifier passes is the exact contract compiled into deterministic
MachineExperience.

Expected invariant:

- frontier resolutions = 8
- verified experience rules = 8

### Episode 2 — KNOWN replay

The same eight semantic keys are resolved through compiled MachineExperience.
The fallback resolver is a hard falsifier: if it is called, the crown fails.

Each native case executes again and must produce the same deterministic
evidence digest.

Expected invariant:

- frontier resolutions = 0
- MachineExperience replay avoidance = 100%
- discovery/replay evidence identity = 8/8

## CMCA is now a planning probe

`autofde_lab.planning.cmca_probe` projects the explicit FOND x HDDL product
frontier into CMCA candidates.

The planner remains the source of semantic possibility. CMCA only decides how
finite planning resources are projected onto that lawful frontier.

Therefore:

- `LAWFUL` is a planning fact.
- `ADMITTED`/zero-allocation is a resource projection.
- a branch receiving no CMCA resources is **not** deleted from the DfCM
  possibility space.
- CMCA remains SELECT; it does not gain CONSTRUCT or DO authority.

The probe derives option value from reachable product topology rather than the
former hard-coded single `option_entropy=8.0` representation of the entire
AutoDev problem.

## Evidence ceiling

`ALIVE` in this demo means the exact **repository-local dogfood-crown subject**
executed and satisfied its falsifiers.

It is intentionally narrower than:

- hosted CI success until a GitHub Actions run is observed;
- production runtime ALIVE;
- cross-repository SA2A closure;
- merge;
- publication;
- deployment.
