## Problem

A2A-2608 requires that generated code be treated as a disposable projection of admitted
semantic state (`C_t = projection(O*, generator, toolchain, environment)`) with no independent
semantic authority, and that repair always targets the admitted source, generator, verifier, or
declared environment — never the generated output directly.

This repo already has two things `.claude/rules/architecture.md` and `CLAUDE.md` rule 4 declare
"generated-only, never hand-edit":

1. `ontology/autofde-lab-capabilities.ttl` — regenerated by
   `python -m autofde_lab.fabric.ontology`, source of truth
   `src/autofde_lab/fabric/ontology.py` (read in full this session).
2. `src/autofde_lab/constitution/` (8 non-`__init__.py` files) — regenerated by `ggen sync run`
   from `ggen.toml` (root, read in full this session, 4668 bytes) driving
   `queries/constitution/*.rq` (8 files, confirmed present) +
   `templates/constitution_module.py.tera` (confirmed present) against
   `ontology/{lab,world,planning,process,authority,evidence,standing,interop}.ttl`.

The open question this ticket answers with evidence, not restated doctrine: does either
generation path actually behave the way A2A-2608's invariant requires — regenerable from
source, provenance-bound, and refusing to let a hand patch to the generated file pass silently
— or is the "generated-only" declaration in `architecture.md` aspirational in one of the two
cases?

**Real finding, load-bearing for this whole ticket**: the two surfaces are **not** the same
mechanism and do **not** have the same standing.

- `ontology/autofde-lab-capabilities.ttl` is written by `generate()`
  (`src/autofde_lab/fabric/ontology.py:522-527`), which opens the target with plain `"w"` mode
  — an unconditional full overwrite, every run, no create/skip branching. Regeneration is
  structurally idempotent-by-construction for this surface.
- `src/autofde_lab/constitution/*.py` is written by `ggen sync run` against **8 separate
  `[[generation.rules]]` blocks in `ggen.toml`, every one of which declares `mode = "Create"`**
  (verified by reading the full file this session — grep for `mode = "Create"` under each of
  the 8 `constitution-*` rule names, vs. `mode = "Overwrite"` on exactly one other rule,
  `planner-league-catalog`). `ggen`'s own real, this-session `--dry-run` output (below) confirms
  what that means operationally: on a tree where the target file already exists, `ggen sync
  run` reports `"skipped: mode=create: target already exists"` for **every one of the 8
  constitution files**, unconditionally — it does not compare content, does not detect drift,
  and does not restore anything. **Regenerating does not regenerate; it is a no-op once the
  file exists once.** A hand patch to `src/autofde_lab/constitution/standing.py` would sit there
  silently forever under routine `ggen sync run` use; nothing about "re-run `ggen sync run` to
  regenerate" (the `architecture.md` / module-docstring instruction) is true for these 8 files
  under the current manifest.

**Blast-radius note, why Severity is Medium and not High locally**: `architecture.md` states
`src/autofde_lab/constitution/` is "Additive only; not wired into any other module." Checked
this session with a real grep (`grep -rln "autofde_lab.constitution\|from autofde_lab import
constitution\|from \.\.constitution\|from \.constitution" src/ tests/`): the only hits outside
`src/autofde_lab/constitution/__init__.py` itself and the 8 `tests/test_constitution_*_chicago.py`
files are the 8 test files (each a Chicago test importing one constitution module directly, as
expected) plus one docstring line, `src/autofde_lab/reasoning/universes/__init__.py:6`, which
*mentions* `autofde_lab.constitution` in prose ("matching the precedent in
``autofde_lab.constitution``") and contains no actual `import` statement — confirmed by reading
that line. Net finding: zero real runtime importers outside the tests, consistent with
`architecture.md`'s claim. A silently-tampered constitution module today changes no runtime
behaviour anywhere else in the package. That containment is exactly why this is `Medium`, not
`High`: the gap is
real, but its current consequence is bounded to a module nothing else consumes yet, not
(per A2A-2608's own framing) "generated code becoming an independent semantic source" for a
live system. `ontology/autofde-lab-capabilities.ttl`, by contrast, **is** consumed —
`tests/ecosystem/test_chatman_chain_chicago.py` and `src/autofde_lab/fabric/coverage.py` both
read it — but that surface's generator is the always-overwrite one, not the `mode = "Create"`
one, so the higher-consequence surface is also the one with the safer generation mechanic.

## Required change

For `src/autofde_lab/constitution/` specifically, at least one of:

1. Change the 8 `constitution-*` rules in `ggen.toml` from `mode = "Create"` to
   `mode = "Overwrite"` (the mode already proven to work in this exact pipeline — the
   `planner-league-catalog` rule uses it and, per this session's real `ggen sync run --dry-run`
   output, is the one rule that reports `"planned: write (dry-run)"` rather than a skip); or
2. Keep `mode = "Create"` (write-once may be intentional for a hand-reviewed constitution) but
   add an explicit, separate drift check — content-hash-level, not the coarser structural check
   `scripts/verify_ggen_generation.py` already runs (see Chicago falsifiers below) — that fails
   closed when a constitution file's content no longer matches what the current ontology +
   query + template would produce, so drift is at least detected even if not auto-repaired.

No change is proposed to `ontology/autofde-lab-capabilities.ttl`'s generator — its
always-overwrite mechanic already satisfies the "regenerate, don't hand-patch" shape; its real
gap (below) is byte-for-byte determinism across environments, not regeneration semantics.

This ticket makes no code change itself — report/evidence-gathering only, per task scope.

## Laws (remote A2A-2608 laws, mapped to real local evidence — none force-fit)

1. **"Source-of-truth identity is the admitted graph/spec identity, not the generated file
   tree."** — `PARTIAL_ALIVE` locally. True in doctrine (`architecture.md`, module docstrings)
   for both surfaces; true in *mechanism* only for `ontology/autofde-lab-capabilities.ttl`
   (always-overwrite). For `constitution/`, the file tree is, in practice, the identity that
   survives once created — `mode = "Create"` means the `.ttl` source can change and the `.py`
   projection will not follow without deleting the target first.
2. **"Generated files carry provenance back to graph, query/template/generator and toolchain
   identities."** — `PARTIAL_ALIVE`, real and non-trivial for `constitution/`: `.ggen-v2/
   receipt.json` and `.ggen-v2/receipt-log.jsonl` (46 real entries this session, tail read in
   full) record, per run, a `closure` map of every `ontology/*.ttl`, `queries/constitution/
   *.rq`, and `templates/*.tera` file to a content hash, plus `"actuator": "ggen@26.8.18"` /
   `"ggen@26.8.28"` (toolchain identity) — this is real, structured, machine-checkable
   provenance of the *generation event*. What it is **not**: provenance embedded *in* the
   generated file itself beyond a plain-English docstring ("GENERATED by ggen. DO NOT EDIT BY
   HAND", `src/autofde_lab/constitution/lab.py:16-17`) — no hash, no graph identity, is carried
   in the `.py` file itself, so a copy of the file divorced from `.ggen-v2/` carries no
   self-describing provenance. `ontology/autofde-lab-capabilities.ttl` has weaker provenance
   still: its own header (lines 6-8) names the generator module and inputs in prose, no hash.
3. **"A direct mutation to generated output fails qualification unless reproduced by the
   manufacturer from admitted source."** — `PARTIAL_ALIVE`, real but coarse-grained.
   `scripts/verify_ggen_generation.py` (read in full this session) is a genuine, independent
   (no `ggen` import or subprocess) qualification check: it re-parses each `ontology/*.ttl`
   with `rdflib` and asserts a **structural cardinality match** — real `owl:Class` count (minus
   SKOS-vocabulary classes) equals real `@dataclass` count in the matching `constitution/*.py`
   file, run for all 8 files plus 3 other generated modules. Run for real this session (see
   Local execution): exit 0, `"standing": "ALIVE"`, all 12 checks `"match": true`. **Named gap**:
   this check is count-based, not content-based — a hand edit that preserves the dataclass
   count (renaming a field, rewriting a docstring, changing a method body, reordering fields)
   would produce identical counts and pass this verifier while genuinely drifting from the
   ontology-derived projection. It is real qualification evidence, not full-fidelity tamper
   detection.
4. **"Regeneration from identical admitted inputs is deterministic within the declared
   environment."** — `UNKNOWN` this session for `ontology/autofde-lab-capabilities.ttl`, for a
   precisely named reason, not a vague one: this session ran
   `.venv/bin/python -m autofde_lab.fabric.ontology <scratch-path>` and diffed the result
   against the committed file (235 lines of diff). Every diffed line is attributable to optional
   extras absent from **this session's** `.venv` (`openap`, `unified_planning`, `pyRDDLGym`,
   `joblib`, `dspy`, `ray`, `sb3_contrib`, `pyRDDLGym_gurobi` — named in the real warning output)
   flipping several domains/solvers from the committed `ALIVE` to a freshly-computed
   `UNSUPPORTED`. This is evidence of **environment drift between this session and whatever
   environment produced the committed file**, not evidence the generator itself is
   nondeterministic — but it also means byte-for-byte determinism was **not confirmed** this
   session, and cannot be, without an environment matching `--extra=all`. For `constitution/`,
   this law is moot under `mode = "Create"`: regeneration from identical inputs is not attempted
   at all once the target exists, so "deterministic" has nothing to be measured against locally.
5. **"Semantic parity gates fail closed on projection drift."** — `PARTIAL_ALIVE` for
   `ontology/autofde-lab-capabilities.ttl` only:
   `tests/ecosystem/test_chatman_chain_chicago.py::TestOntologyIsGeneratedNotCurated` (read
   lines 491-608 this session) contains real, independent drift assertions —
   `test_ontology_matches_live_registry_exactly` and `test_ontology_covers_every_declared_kind`
   — that fail closed (hard `assert`, named missing/stale sets on failure) if the committed
   `.ttl` drifts from the live registry. No equivalent registry-drift gate exists for
   `constitution/`; `scripts/verify_ggen_generation.py` (law 3, above) is the closest local
   analogue and is coarser.
6. **"Generated code never grants authority by existing."** — `ALIVE` for both surfaces, on
   real evidence already established outside this ticket and re-confirmed by reading
   `src/autofde_lab/constitution/lab.py:1-17` and `fabric/ontology.py:97-104` (`VOCABULARY_CEILING`)
   this session: both carry an explicit claim-ceiling in their own docstrings/constants stating
   the artifact is "additive only, not wired into any... runtime code path" (constitution) or
   "NOT a claim that anything was computed, executed, admitted, actuated, or verified"
   (ontology). Neither file's presence is treated anywhere in this repo's own source as an
   authority or admission grant — consistent with `src/autofde_lab/CLAUDE.md`'s Non-authority
   section.

## Chicago falsifiers (remote falsifiers, mapped — none re-derived from the remote text, each
checked against a real local test or named absent)

1. **"Tampering with one generated line without changing `O*` causes qualification failure."**
   — `PARTIAL_ALIVE` for `constitution/` (via `scripts/verify_ggen_generation.py` +
   `tests/test_verify_ggen_generation_chicago.py`, run this session, see Local execution) —
   *only* for a tamper that changes the `@dataclass` count; a same-count content tamper is
   `NOT_FOUND` — no local test exercises that case. `UNKNOWN` for
   `ontology/autofde-lab-capabilities.ttl`: the registry-drift tests (law 5) would only fail if
   a tamper also broke registry/ontology set-equality, not for a same-membership content edit
   (e.g. hand-editing `skdt:evidence` text) — no falsifier test for that exists either.
2. **"Regenerating restores the canonical projection byte-for-byte where determinism is
   promised."** — `BLOCKED:GGEN_MODE_CREATE_SKIPS_EXISTING_TARGETS` for `constitution/` — this
   is the ticket's central real finding (see Problem): regeneration is a **structural no-op**
   on an existing target under `mode = "Create"`, confirmed by this session's real
   `ggen sync run --dry-run` output. It cannot restore anything because it does not run.
   `UNKNOWN` for `ontology/autofde-lab-capabilities.ttl` per law 4 above — the mechanism runs
   unconditionally, but this session could not confirm byte-for-byte identity because of a
   real, named environment mismatch, not a generator defect.
3. **"A change to `O*` produces a new projection identity and receipt."** — `ALIVE` for
   `constitution/`'s receipt half only: `.ggen-v2/receipt-log.jsonl`'s 46 real entries (grep +
   parse run this session) show `graph_hash`/`closure` hashes changing run-to-run as source
   files changed (e.g. entries 0→1→2 show different `graph_hash`/output sets as
   `domain_evidence_registry.py` and others were written across the session history that
   produced this log) — receipts do change with input change, for files whose rule mode
   actually re-runs. It is **not** independently confirmed for the 8 `mode = "Create"`
   constitution files specifically, because none of the 46 real logged runs ever re-wrote one
   (every one of their `decisions` entries across all 46 lines reads
   `"skipped: mode=create: target already exists"` — checked this session by parsing the whole
   log, not sampled) — so whether a projection identity *would* change for them is, honestly,
   `UNKNOWN`, since the write path that would prove it has real code (`mode = "Overwrite"`,
   proven elsewhere in the same manifest) but has never actually executed against these 8
   rules.
4. **"A generated artifact with missing provenance cannot be promoted."** — `NOT_FOUND` locally
   for both surfaces. Nothing in this repo's source, tests, or CI configuration (not searched
   exhaustively for CI in this pass; scope was source + tests) gates a commit, merge, or release
   on a generated file's provenance being present. `.ggen-v2/receipt-log.jsonl` exists and is
   real, but nothing consumes it as an admission gate in this repo — it is closer to a passive
   audit log than a promotion gate. No "promotion" concept (in the admission sense) exists
   locally at all — consistent with `.claude/rules/ecosystem-boundary.md`: this repo has no
   admission authority to promote anything into.
5. **"A consumer cannot treat a generated artifact as a new ontology/source without explicit
   re-admission."** — `UNKNOWN` locally; no local consumer of `constitution/` exists to test
   this against (it is unwired, per the Problem section), and `ontology/autofde-lab-
   capabilities.ttl`'s one real local consumer
   (`src/autofde_lab/fabric/coverage.py::load_ontology`) was not read this session to determine
   whether it could be tricked into treating a hand-edited copy as a fresh source — out of
   scope for this pass, named here rather than guessed at.
