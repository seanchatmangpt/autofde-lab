# RFC-SA2A-002 Compliance Matrix

This is the compliance matrix RFC-SA2A-002 §145 ("Compliance Matrix Requirement")
itself calls for: RFC requirement → mapped conformance test ID or evidence →
result, for every numbered section of `docs/rfcs/RFC-SA2A-002-v26.9.16.md` that
carries a MUST/SHOULD/MAY/SHALL sentence.

## Summary

**283 requirements** were extracted from RFC-SA2A-002 v26.9.16 (sections 1–147,
140 distinct numbered sections that carry normative text; sections with no
MUST/SHOULD/MAY/SHALL sentence, e.g. §87/§89/§91/§94's zero-content benchmark
placeholders, contribute no rows). Of those:

- **135 requirements (47.7%) are MAPPED** — a real test ID, source-line citation,
  or session-executed command backs the claim.
- **148 requirements (52.3%) are GAP** — no mapped test or evidence was found in
  this repository as of `f5727fa9` (this branch's current HEAD per the session's
  `git status`), per this repo's `absence-is-not-evidence.md`: absence of a found
  test is recorded as `GAP`, never coerced into `MAPPED`.

These counts come directly from the 293 raw requirement rows extracted by 8
parallel reviewers covering the full RFC in overlapping line ranges, deduplicated
to 283 rows by collapsing 10 requirements that were independently re-extracted at
a chunk boundary (same section number, same normative level, ≥45% text-similarity
match, confirmed to originate from adjacent/overlapping chunk ranges — sections
15, 53, 75 (×3), 95 (×2), 115 (×2), and 144). Where two overlapping extractions
disagreed on MAPPED vs. GAP for the same requirement (sections 53 and 115), the
more conservative (GAP) finding was kept, consistent with this repo's
`no-dual-bookkeeping.md`: a partial-coverage finding does not get rounded up to
full coverage.

**Many "MAPPED" rows are themselves partial** — the evidence column says so
explicitly wherever a reviewer found only a subset of a multi-item requirement
covered (e.g. §5's exact-subject fields, §54's 9 named envelope defects). This
matrix reproduces each reviewer's own gap/partial framing rather than rounding
partial coverage up to a clean MAPPED.

Several rows reflect requirements that were live-executed this session and found
`BUILD_BROKEN` as of HEAD `f5727fa9` (benchmarks B1, B2, B4, B9 in §85/§86/§88/§93)
rather than merely un-mapped — those rows are still marked GAP in the Result
column (no passing evidence exists), with the BUILD_BROKEN detail preserved in
the evidence text itself.
