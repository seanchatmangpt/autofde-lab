# Role

Holds `autofde-lab-capabilities.ttl`, the machine-readable capability graph of this repository:
which domains and solvers exist, whether each actually imports, what domain characteristics
each solver requires, and which PDDL requirements are unsupported.

# Authority

- Be the **queryable** answer to "which admitted capability does X?", replacing the
  unanswerable "have I looked everywhere?". This is an epistemic control, not documentation: a
  false ecosystem claim was made in this repo's history from a search that had simply never
  looked at one of the sibling repositories.
- Encode the silent-wrong-answer PDDL hazard as a first-class fact (4 `UNSUPPORTED`
  requirements of 16) rather than as a constant buried in one module.

# Non-authority

- **Not authored.** The file is generated; hand-edits are defects, not contributions.
- Scoped to *this repository*. It is not an ecosystem-wide ontology — repositories, crates,
  renamed/absorbed components, actuators, and verification rails are not modelled here. That
  graph is recorded as scoped-not-done in `docs/ecosystem-standing.md`.
- Declares no ranking, no preference, and no admission. `skdt:standing "ALIVE"` on a capability
  means *it imported in the probing environment*, nothing more.

# Inputs

`pyproject.toml` entry points (the authoritative registry) + a live import probe +
`Solver.get_domain_requirements()` MRO derivation.

# Outputs

`autofde-lab-capabilities.ttl` — Turtle, prefixes `skd:` (`urn:skdecide:capability:`) and `skdt:`
(`urn:skdecide:term:`). Current content: 83 capabilities (26 domains, 57 solvers) plus 16 PDDL
requirements, 4 `UNSUPPORTED`.

# Invariants

1. **Regenerate, never hand-edit**:
   `python -m autofde_lab.fabric.ontology ontology/autofde-lab-capabilities.ttl`. The file carries
   its own `# GENERATED by autofde_lab.fabric.ontology -- do not hand-edit.` header.
2. `tests/ecosystem/` fails if the file drifts from the live registry, and separately asserts
   that each solver's recorded requirements **equal** its `get_domain_requirements()`
   derivation — requirements are derived, not asserted.
3. A capability that fails to load must appear as positive `UNSUPPORTED` evidence, not vanish
   (`utils.py:94` returns `None` on load failure rather than raising).
4. `standing` values use the repo vocabulary: `ALIVE` / `PARTIAL_ALIVE` / `BLOCKED:<reason>` /
   `BUILD_BROKEN` / `UNKNOWN` / `UNSUPPORTED`.
5. Applicability recorded here is necessary, not sufficient, for runnability — constructor
   requirements are outside the derivation (7 solvers are applicable yet not runnable with
   defaults).

# Neighboring components

`src/autofde_lab/fabric/ontology.py` (generator), `src/autofde_lab/fabric/coverage.py` (consumer —
classifies every declared capability against a concrete domain), `src/autofde_lab/utils.py`
(registry), `tests/ecosystem/test_chatman_chain_chicago.py` (drift assertions),
`docs/ecosystem-standing.md` §S8.

# Verification

```bash
uv run python -m autofde_lab.fabric.ontology ontology/autofde-lab-capabilities.ttl
git diff --exit-code ontology/autofde-lab-capabilities.ttl    # must be empty if registry unchanged
uv run pytest tests/ecosystem/
```

# Standing ceiling

Strongest establishable claim: **"the set of registered capabilities and their derived domain
requirements is exactly this, in this environment, at this commit"** — verified by regeneration
producing a byte-identical file and by the drift tests passing.

Not establishable from this file: that a capability *runs* (import ≠ execution), that one
capability is better than another (no ranking exists anywhere in this repo), that the set is
complete across the portfolio (repo-scoped only), or that any capability's output is admitted.
An `ALIVE` row is an import receipt, not a solve receipt.

# Update obligations

- Any entry-point change, any `T_domain` change, any new PDDL requirement classification →
  regenerate in the same commit.
- If the generator's inputs change (e.g. a new probe source), update the header comment inside
  the generated file via the generator, and `docs/ecosystem-standing.md` §S8's counts.
- Never resolve a drift-test failure by editing the `.ttl`; fix the registry or regenerate.
